## 🎯 The Problem

Tunisia's tourism sector is losing ground — underused infrastructure, artisans invisible to global markets, and fragmented booking experiences scattered across a dozen disconnected tools.

**TunisiaTour** isn't another booking app. It's a **full national tourism ecosystem** — built by 6 engineering students at ESPRIT — that unifies accommodation, transport, flights, events, and artisan commerce into one intelligent, AI-powered platform, running on a **private cloud infrastructure we built entirely ourselves.**

## 🧩 Platform Modules

🏨 **Accommodation** — geolocation, 360° galleries, dynamic pricing, verified reviews
🚖 **Ride / Taxi** — live GPS tracking, multilingual real-time chat (STT/TTS), transparent fares
✈️ **Flights** — multi-airline search, price comparison, e-tickets
🎭 **Events** — AI-powered recommendations, integrated ticketing with QR codes
🛍️ **Artisans Marketplace** — authenticity labels, AI-generated product visuals, storytelling
🤝 **Community Hub** — themed groups, voice messages, live location sharing
🔐 **Security** — Face ID login, two-factor authentication (2FA)
🌐 **Multi-role Ecosystem** — tourists, professionals, artisans, admins — one unified back office

## 🏗️ Infrastructure — Built From Bare Metal to Production

This isn't a hosted app — it's a **self-built private cloud**, engineered end-to-end:

```
        ☁️ OpenStack Private Cloud
   1 Controller · 5 Compute · 1 Storage Node
   Keystone · Nova · Neutron · Glance · Cinder · Heat · Horizon
                     │
        ⚙️ Ansible — full automation (agentless, SSH)
                     │
        🐳 Docker — containerized services
                     │
        ☸️ Kubernetes (1 Master + 2 Workers) via Helm
                     │
        📊 Prometheus + Grafana — real-time monitoring
                     │
        🧠 AIOps — anomaly detection on live metrics
                     │
        🚀 TunisiaTour Application (Angular + Spring Boot + MySQL)
```

**Key achievements:**
- Full VM lifecycle provisioning (Keystone → Nova → Scheduler → Conductor → KVM)
- Advanced networking: VXLAN tunnels, Floating IPs, virtual bridges
- Multi-tenancy, self-healing, orchestration via Heat
- Horizontally scalable, highly available Kubernetes cluster
- Custom alerting (CPU > 80%, pod failures) + baseline-deviation anomaly detection
